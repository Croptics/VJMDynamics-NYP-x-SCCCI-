MUSTERGO — PROJECT STRUCTURE NOTES
====================================
(What each file does, organized by folder)


ROOT LEVEL
----------
permissions.js
    The single source of truth for permissions. Both frontend and backend
    import this one file. Defines the 5 permissions (manageDelegates,
    manageTrips, manageExceptions, exportData, manageAccounts) — add one
    entry here and the checkbox/chip/enforcement appear everywhere
    automatically.

README.md / HIGH_LEVEL_DESIGN.md / PROJECT_IMPLEMENTATION_PHASE.md
    Docs — setup instructions, architecture/DB schema notes, and the team's
    sprint plan.

.gitignore
    Excludes .claude/, node_modules/, and other local-only files from git.

.claude/
    My (Claude Code) own tooling config — dev-server launch settings etc.
    Not part of the app itself; gitignored, never pushed to GitHub.


BACKEND/  (Express API, port 4000)
-----------------------------------
server.js
    The Express app itself. Defines every API route: login/session,
    dashboard reads, delegate CRUD, Excel export, account management.
    Read routes (trips/dashboard/missing/delegates) require any signed-in
    account via requireAuth(); mutating routes and export require a
    specific permission via requirePermission() (both from auth.js). Has a
    "TEAMMATE ZONE" comment near the bottom — the sanctioned spot for
    teammates to plug in their own route files (e.g. routes/insights.js
    is mounted here).

auth.js
    Session tokens + auth middleware, shared by server.js and any
    teammate route file that needs to require a signed-in caller (e.g.
    routes/insights.js, routes/desmond.js, routes/exceptions.js). Issues
    signed JWTs (makeToken) and exports accountFromReq / requireAuth /
    requirePermission. accountFromReq also accepts the token as a ?token=
    query param (not just the Authorization header) — needed for Jayden's
    SSE route, since EventSource can't set custom headers. Set JWT_SECRET in
    backend/.env before deploying anywhere public — without it a fixed
    dev-only fallback is used and a warning prints on startup.

data.js
    The database layer — talks to PostgreSQL. Creates the schema/seed
    data on first run, and exports functions like getDashboard(),
    getMissing(), listDelegates(), account CRUD, etc. server.js just
    calls these. Passwords are stored as bcrypt hashes (hashPassword /
    verifyPassword). Older rows created before hashing was added are
    auto-upgraded in place the next time that account logs in
    successfully (upgradePasswordIfNeeded) — no manual migration needed.
    Also creates Desmond's "TransitFlow" schema (the users + itinerary_items
    tables and the extra trip/coach/delegate columns his Trips board needs) —
    folded into createSchema()/seed() so it auto-applies on startup, instead
    of the standalone SQL migration files his feature originally shipped with.

routes/desmond.js
    Desmond's "TransitFlow" API — the Trips & Coaches board (list trips,
    per-trip coach/delegate/itinerary CRUD, staff directory, seed demo
    trips, in-memory activity feed). Self-contained: makes its own pg pool.
    "View for all, edit gated": every GET route (and the cosmetic POST
    .../activity) uses requireAuth() (any signed-in account); every other
    write route uses requirePermission("manageTrips") — applied per-route,
    not as one router-level gate, since a blanket gate would also catch
    requests meant for OTHER teammates' routers mounted alongside this one
    (found and fixed while merging in Jayden's exceptions.js). Mounted in
    server.js's TEAMMATE ZONE next to insightsRouter. To avoid colliding
    with the base app's hardcoded single-trip routes it uses new paths like
    /api/all-trips and /api/trips/:tripId/summary.

routes/exceptions.js
    Jayden's Exception Logging & QR Fallback API — ticket CRUD (raise/
    resolve/delete), manual attendance override, and a live Server-Sent
    Events channel (GET /api/exceptions/stream) that pushes ticket changes
    to every connected staff device in real time. Self-contained: makes its
    own pg pool and creates its own tables (exception_tickets, shared
    check_in_logs) via initExceptions(), called once from server.js's
    startup chain after initDb(). "View for all, edit gated": reads (+ the
    SSE stream) use requireAuth(); raising/resolving/deleting a ticket or a
    manual override use requirePermission("manageExceptions"). Its original
    auth code decoded the old pre-JWT token format by hand — rewritten at
    merge time to use auth.js's requireAuth/requirePermission like every
    other route.

backend/seed-demo.js
    One-off script (npm run seed:demo) that seeds a realistic delegate
    roster (via data.js's own createDelegate, so rows are shaped exactly
    like the rest of the app expects) plus 7 sample exception tickets, so
    the Exceptions inbox and Trips board aren't empty on a fresh database.
    Safe to re-run — skips seeding whatever already exists.

backend/reset-login.js
    One-command fix (npm run reset:login) for "I cloned the repo and can't
    log in." The team shares ONE Neon database and `git clone` only resets
    CODE, not the DB — the seeded staff_194/password123! login only applies
    on a first boot against an empty DB, so once the shared DB drifts (a
    changed password, a teammate's old branch writing to accounts) the
    documented credentials stop working. This force-resets staff_194 back to
    password123! with full main permissions (creating it if missing). Safe
    to re-run; override target with RESET_USER / RESET_PASS env vars.

routes/insights.js
    Powers the "Generate Insights" button on the Dashboard's Analytics tab.
    Requires a signed-in account (requireAuth, from auth.js). Tries a
    local Ollama server first (free, no key, nothing leaves your
    machine); if Ollama isn't running, falls back to the Anthropic API
    (needs ANTHROPIC_API_KEY in .env). If neither is available, returns a
    clear "not configured" message instead of erroring. Also honors the
    current UI language — asks the model to write directly in English or
    Chinese, so no separate translation step is needed.

package.json / package-lock.json
    Dependencies (express, pg, exceljs, cors, dotenv, @anthropic-ai/sdk,
    bcryptjs, jsonwebtoken) and the scripts: "npm run dev", "npm start",
    "npm run seed:demo", "npm run reset:login".

.env  (gitignored, not shown in file list)
    Holds DATABASE_URL for your Postgres connection, JWT_SECRET for
    signing session tokens (see auth.js above), and optionally
    OLLAMA_HOST / OLLAMA_MODEL / ANTHROPIC_API_KEY / ANTHROPIC_MODEL for
    the AI Insights feature. See .env.example for the full list with
    explanations.


FRONTEND/  (React + Vite SPA, port 5173)
------------------------------------------

Entry point & routing:

  main.jsx
      The actual entry point — mounts React to the DOM, wraps everything
      in BrowserRouter and LanguageProvider (the translation context),
      imports the global tokens.css.

  App.jsx
      The router. Decides auth state, and maps every URL path
      (/dashboard, /assistant, /mobile, etc.) to its page component.
      This is the file to check first when you want to know "what page
      does this URL show." Also remembers whether you were in the mobile
      section before logging out, so signing back in returns you there.

  vite.config.js
      Dev server config — proxies /api/* calls to the backend on :4000
      so the frontend never needs to think about CORS.

Shared components (src/components/):

  Layout.jsx
      The desktop shell — renders Sidebar + whatever page is routed into
      the main content area. Also polls the backend every 15s to catch
      if your account got edited/deleted while logged in, and separately
      polls lib/exceptionsApi.js's getCriticalOpenCount() every 15s to
      drive the Sidebar's live "Exceptions" badge (used to be hardcoded
      demo state).

  Sidebar.jsx
      The left nav rail — links to every page, the EN/中文 toggle, and
      the account/logout block at the bottom.

  StatusBadge.jsx
      Small reusable pill component for status labels (Present/Missing/
      Unassigned/etc.) and confidence-score badges.

  AnalyticsPanel.jsx
      Rendered inside the Dashboard's "Analytics" tab. Contains: the
      charts + "Customize" widget-toggle UI, and the "AI Insights" card
      with the "Generate Insights" button (calls backend/routes/insights.js,
      shows which source answered — local Ollama or Claude — and respects
      the current language).

  LogExceptionModal.jsx
      Jayden — the "Log exception" create form (issue type, delegate
      picker, note, "Mark as critical" toggle). Only reachable via the

Library helpers (src/lib/):

  api.js
      The HTTP client — apiGet/apiPost/apiPatch/apiDelete, all
      auto-attaching your JWT. Also handles token/user storage (login
      persistence).

  i18n.jsx
      The translation system — the English/Chinese dictionary,
      useLang() hook (returns { lang, toggleLang, t }), and language
      toggle logic. Also exports translate() for code outside React
      rendering (e.g. window.alert/confirm messages). Static dictionary
      only — no data ever sent to a translation API, so delegate
      names/live data are never exposed.

  claudeParse.js
      Simulated document-parsing helper for the Onboarding page
      (unrelated to the AI Insights feature — this is Vance's

  exceptionsApi.js

HOW TO TRACE A PAGE
--------------------
1. Start at App.jsx to find which page a URL loads.
2. Open that page file.
3. If it needs live data, it calls apiGet/apiPost from lib/api.js.
4. That hits a route in backend/server.js (or backend/routes/*.js).
5. Which calls a function in backend/data.js (or, for AI Insights,
   talks to local Ollama / the Anthropic API).


AUTH & SECURITY
-----------------
- Session tokens are signed JWTs (backend/auth.js), not forgeable.
  Set JWT_SECRET in backend/.env before deploying anywhere public.
- Passwords are bcrypt-hashed (backend/data.js). Legacy plaintext rows
  auto-upgrade on next successful login — nobody needs to run a migration.
- Every API route requires a signed-in account at minimum; mutating
  actions (delegate CRUD, accounts, export) additionally require the
  matching permission from permissions.js, enforced server-side (not
  just hidden in the UI).
- Because tokens changed format, everyone gets signed out once after
  this update and needs to log back in — expected, one-time.


TESTING THE MOBILE UI ON A PHONE
-----------------------------------
Both dev servers already support this (vite.config.js has host: true,
Express listens on all interfaces by default) — no code changes needed:

  1. Connect your phone to the same Wi-Fi as this computer.
  2. Run `npm run dev` in both backend/ and frontend/ as usual.
  3. Find this computer's local IP (Windows: ipconfig -> IPv4 Address,
     e.g. 192.168.1.11).
  4. On the phone's browser, go to http://<that-IP>:5173/login, sign in,
     and it'll land you on /mobile automatically.
  5. If it won't load, Windows Firewall is the usual culprit — allow
     Node.js through the firewall for Private networks (or allow ports
     5173/4000). The phone only needs port 5173 — Vite's dev proxy
     forwards /api/* to the backend on this machine's side.


AI INSIGHTS — RUNNING IT LOCALLY
----------------------------------
Two options, tried in this order automatically — no code changes needed
to switch between them:

  a) Local Ollama (free, no API key, nothing leaves your machine)
     1. Install from ollama.com
     2. Run: ollama pull llama3.2
     3. Leave it running in the background — auto-detected at
        http://localhost:11434

  b) Anthropic API (used automatically if Ollama isn't running)
     1. Get a key at console.anthropic.com
     2. Add to backend/.env:  ANTHROPIC_API_KEY=sk-ant-...

If deploying the backend to a live hosting service, only option (b)
works there — the deployed server has no access to your laptop's
Ollama. Add ANTHROPIC_API_KEY as an environment variable on the
hosting platform (Vercel/Render/etc.) for AI Insights to work live.


CAN'T LOG IN AFTER CLONING? (shared-database gotcha)
--------------------------------------------------------
The team shares ONE Neon database. `git clone` resets your CODE but NOT the
database — so the seeded `staff_194 / password123!` login (which only runs
on a first boot against an empty DB) may not match what's currently stored
in the shared DB. If someone changed the password, or a teammate on an older
pre-bcrypt branch wrote to the accounts table, the documented credentials
stop working for everyone.

Fix it in one command (no more editing Neon by hand):

  cd backend
  npm run reset:login        # staff_194 back to password123!, full access

Note: because logins now enforce a single active session, when YOU reset and
log in, other people's staff_194 sessions get logged out. Longer term, each
developer having their own Neon database (free tier allows several) avoids
this class of problem entirely.


EXCEPTIONS FEATURE — SEEDING DEMO DATA
------------------------------------------
The Exception inbox and Trips board start empty on a fresh database (the
base app only seeds a trip, 4 coaches, and the first login). To populate
them with a realistic delegate roster + 7 sample tickets:

  cd backend
  npm run seed:demo

Safe to re-run — it skips seeding whatever already exists. By default,
new accounts (and any created before this feature) don't have the
"Manage exceptions" permission — grant it in Account Control to let an
account raise/resolve/delete tickets or do a manual override; everyone
signed in can already view the inbox and live alerts.
